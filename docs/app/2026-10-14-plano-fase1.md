# App NutriBot — Plano da fase 1 (primeiro APK)

**Data:** 14/10/2026 · **Branch:** `app-fase1` · **Base:** relatório da rodada 1 (`2026-10-13-relatorio-rodada-1.md`) e o protótipo aprovado pelo dono.

## Objetivo

Entregar o **primeiro APK instalável** do app novo, lendo **dados reais**:

- telas Hoje, Comida (diário por dia), Progresso, Corpo (versão inicial), Nutri e Integrações;
- menu do nome com Perfil, Agenda e Resumos;
- o app substitui o Relógio **só no celular do dono**: mesmo `applicationId` (`br.nutribot.relogio`) e mesma chave de assinatura, então instala por cima e mantém as permissões e a sincronização do Health Connect, da localização e do cupom.

## Regras

- Branch `app-fase1`. Nada vai para `main` (que dispara deploy no Render) sem revisão. A API é só **aditiva**: nenhuma rota existente muda e o WhatsApp não muda.
- Custo zero. Nenhum segredo no app. Os dados das 3 pessoas só saem com token de aparelho.
- O APK novo é publicado na release **`app`**. A release `relogio` não muda, e as outras pessoas continuam com o Relógio antigo (D1).

## Contrato da API v1 (servidor ↔ app)

Base: `https://nutribot-5gwk.onrender.com/api/v1`.

- **Autenticação:** cabeçalho `Authorization: Bearer <token>`.
- **Erros:** `{ "erro": { "codigo": "...", "mensagem": "..." } }`, com o status HTTP correspondente (400, 401, 403, 404, 500, 503).
- **Datas:** `dia` em `YYYY-MM-DD` no fuso da pessoa; `hora` em `HH:MM` local.

### Pareamento

- No WhatsApp, o dono manda `!app` **no privado** com o bot (só o `ADMIN_JID`). O bot responde com um código de 6 dígitos, válido por 10 minutos e de uso único. No Mongo fica só o hash, na coleção `codigos_app`.
- `POST /parear` com `{ "codigo": "123456", "aparelho": "nome do celular" }` devolve 200 `{ "token": "<32 bytes base64url>", "perfis": [...] }`.
  - O token é guardado só como hash (sha256) em `dispositivos`: `{ hash, aparelho, criadoEm, ultimoUso, revogadoEm }`.
  - Erros: 401 `codigo_invalido` e 429 `muitas_tentativas` (5 por hora).
- `!app sair` revoga todos os aparelhos.

### Leitura (MVP)

**`GET /perfis`** devolve `{ "perfis": [Perfil] }`, onde:

```
Perfil = { id, nome, primeiroNome, apelido, fuso, objetivo, metaPeso, metaPrazo, temRelogio, temHevy, ehDono }
```

`id` é o `_id` do documento `perfis`, como string. Os `jids` nunca saem.

**`GET /perfis/:id/hoje?dia=`** devolve:

```
{ dia, fuso, agora,
  kcal: { consumido, faixa: {min,max}|null, err, situacao: 'abaixo'|'dentro'|'acima'|null },
  macros: { proteina: {g, meta}, carbo: {g, meta|null}, gordura: {g, meta|null} },
  refeicoes: [Refeicao],
  pendentes: [{ slot, nome }],
  peso: { atual, kgSemana, ic: {min,max}, veredito, texto } | null,
  relogio: { sonoMin, passos, gastoKcal, gastoPrevisto, fcRepouso, treinos: [{nome, min, hora}], atualizadoEm } | null,
  energia: { nota, sono, recuperacao, carga, texto } | null,
  avisos: [{ tom: 'bom'|'atencao'|'cuidado', titulo, texto }],
  brotinho: { dias, murcho },
  resumoSemana: { texto } | null }

Refeicao = { id, slot, nome, hora, kcal, faixa: {min,max}, p, c, g, descricao, origem, itens: [{ nome, gramas|null, kcal|null }] }
```

Os itens com gramas ainda não existem no banco: nesta fase vêm da descrição (nome, gramas null). A barra em gramas da Comida aparece só quando houver gramas, na fase 2.

**`GET /perfis/:id/refeicoes?de=&ate=`** (no máximo 31 dias) devolve:

```
{ dias: [{ dia, completo, kcal, p, c, g, refeicoes: [Refeicao] }] }
```

**`GET /perfis/:id/progresso`** devolve:

```
{ pesagens: [{ dia, peso, gordura, fonte, hora, descartada, motivo }],
  tendencia: { kgSemana, ic: {min,max}, pesoHoje, direcao, janelas: [{dias, kgSemana}] } | null,
  veredito: { status, prob, texto } | null,
  meta: { min, max, texto } | null,
  alertas: [{ tipo, texto }],
  texto }
```

`texto` é o mesmo `textoZap` do `!progresso`.

**`GET /perfis/:id/corpo`** devolve a composição (gordura e massa magra por medição, com fonte e data), o treino da semana por grupo muscular vindo do Hevy, as sugestões de carga e as medidas (vazio por enquanto).

**`GET /perfis/:id/nutri`** devolve:

```
{ fatos: [...], hipoteses: [...], diario: [{dia, texto}], avaliacoes: [...] }
```

Cada item traz `natureza`, `origem` e `atualizadoEm`.

**`GET /perfis/:id/resumos`** devolve a última semana e o último mês, a partir do que o bot já calcula.

**`GET /integracoes`** devolve o estado de cada fonte: WhatsApp, relógio (último envio e versão do app), Hevy, Drive e agenda.
