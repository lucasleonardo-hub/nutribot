# App NutriBot — Plano da fase 2 (escrita pelo app)

**Data:** 14/10/2026 · **Branch:** `app-fase2` · **Base:** fase 1 no ar (862076a) e o pedido do dono: registrar refeição por foto e texto, ajustar por gramas, humor, eventos que a Nutri lê, peso e meta pelo app.

## Objetivo

O app passa a **escrever**, sem duplicar a lógica do bot: cada rota nova chama a mesma função que o WhatsApp já chama (`registrarRefeicao`, `atualizarRefeicao`, `apagarRefeicaoPorId`, `registrarPesagem`, `aplicarAtualizacao`). O que o bot não tinha (humor, eventos criados pela pessoa, itens com gramas) nasce aditivo: coleções e campos novos, nenhum existente muda de significado.

## Regras

- Branch `app-fase2`; `main` só depois dos testes e da revisão. A API continua aditiva. O WhatsApp muda em UM ponto, de leitura: o prompt da Nutri ganha o bloco "PELO APP" (humor de hoje e eventos dos próximos dias), no mesmo lugar do bloco da agenda.
- Toda escrita confere o dono: o registro precisa ter `jid` entre os `jids` do perfil pedido. 404 quando não é dele.
- `dia` sempre no fuso da pessoa; até 31 dias para trás; nunca no futuro (eventos podem ser futuros, até 60 dias).
- Fotos **não** ficam guardadas (como no WhatsApp). Só uma **miniatura** (JPEG ≤ 24 KB em base64, feita pelo app) fica no registro, para o diário mostrar o prato.
- Nenhum segredo no app; nada da foto vai para log.

## Contrato (aditivo ao da fase 1)

Base, autenticação, erros e datas como na fase 1. `PUT` para alterar (o `HttpURLConnection` do Android não manda `PATCH`), `DELETE` para apagar.

### Refeição

`Refeicao` ganha: `itens: [{ nome, gramas|null, kcal|null, p|null, c|null, g|null }]` (gramas e kcal preenchidos quando a análise veio do app), `miniatura: "data:image/jpeg;base64,..."|null`, `incerteza: 'alta'|'media'|'baixa'|null`, `dia`.

**`POST /perfis/:id/refeicoes`** (JSON até 4 MB)

```
{ texto?: string ≤500, fotos?: [{ mime: 'image/jpeg'|'image/png'|'image/webp', base64 }] (≤2, ≤2 MB cada),
  miniatura?: base64 JPEG ≤24 KB, slot?: cafe|lanche_manha|almoco|lanche|jantar|ceia, hora?: 'HH:MM' (local), dia?: YYYY-MM-DD }
```

Precisa de `texto` ou `fotos`. A IA estima (`ia.estimarRefeicaoApp`: kcal, macros, incerteza, itens com gramas) e o servidor grava com `registrarRefeicao({ ..., manual: true, sempreNova: true, origem: 'app', itens, miniatura })`, igual ao `!refeicao`, e anota na memória do dia (`lembrar`).

- 201 `{ refeicao: Refeicao, hoje: Hoje }` (o `/hoje` do dia gravado, já recalculado).
- 400 `refeicao_invalida`; 422 `nao_e_refeicao` quando a IA diz que a foto/texto não é comida consumida (nada é gravado); 503 `ia_indisponivel`.

**`PUT /perfis/:id/refeicoes/:rid`**

```
{ kcal?, p?, c?, g?, descricao? ≤220, slot?, hora?: 'HH:MM', itens?: [{ nome, gramas }] }
```

Com `itens`, o servidor recalcula kcal e macros na proporção das gramas de cada item (`aplicarGramas`, pura); `kcal/p/c/g` explícitos no corpo vencem o recálculo. Grava com `atualizarRefeicao`, e se a kcal mudou registra o par antes/depois em `correcoes_estimativa` (origem `app`) e uma linha em `correcoes_dia`.

- 200 `{ refeicao, hoje }` · 404 `refeicao_nao_encontrada` · 400 `refeicao_invalida`.

**`DELETE /perfis/:id/refeicoes/:rid`** → 200 `{ apagada: true, hoje }` (e `correcoes_dia`).

### Humor

**`PUT /perfis/:id/humor`** `{ dia?, humor: 1..5, energia?: 1..5, sono?: 1..5, texto? ≤200 }` → 200 `{ humor, hoje }`.
Coleção `humor` (uma por `{jid, dia}`): `{ jid, nome, dia, humor, energia, sono, texto, atualizadoEm }`.
`Hoje` ganha `humor: { humor, energia, sono, texto, atualizadoEm } | null`.

### Eventos (agenda da pessoa, que a Nutri lê)

`Evento = { id, dia, hora|null, titulo, tipo, nota|null, criadoEm }`, `tipo ∈ comer_fora|festa|viagem|treino|consulta|outro`.

- **`POST /perfis/:id/eventos`** `{ dia, hora?, titulo ≤80, tipo, nota? ≤200 }` → 201 `{ evento }`.
- **`GET /perfis/:id/eventos?de=&ate=`** (≤ 62 dias; `ate` até 60 dias à frente) → `{ eventos: [Evento] }`.
- **`DELETE /perfis/:id/eventos/:eid`** → `{ apagado: true }`.
- Cada dia de **`GET /refeicoes`** ganha `eventos: [Evento]`.

Coleção `eventos_app`: `{ jid, nome, dia, hora, titulo, tipo, nota, criadoEm }`.

### Peso

**`POST /perfis/:id/pesagens`** `{ dia?, peso (25–400), gordura? (3–70), hora?: 'HH:MM' }` → 201 `{ pesagem: { dia, peso, gordura, fonte: 'app', hora } }`. Grava com `registrarPesagem({ fonte: 'app' })`: uma por dia nessa fonte; o relógio continua vencendo na consolidação.

### Perfil

**`PUT /perfis/:id`** `{ objetivo?, metaPeso?|null, metaPrazo?: YYYY-MM-DD|null, altura?, ritmo?: maximo|medio|minimo }` → 200 `{ perfil: Perfil }`. Passa por `aplicarAtualizacao` (as mesmas faixas e datas em `perfil.atualizacoes`) e `salvarPerfil`; `metaPeso: null` tira a meta.

### A Nutri lê o que veio do app

No prompt da conversa (mesmo lugar do bloco AGENDA), bloco `PELO APP` com: humor/energia/sono de hoje (e o texto, se houver) e os eventos de hoje e dos próximos 3 dias. Regra no prompt: usar como contexto da pessoa (um jantar fora hoje muda a dica do almoço; humor baixo pede resposta mais leve), sem comentar com outra pessoa.
